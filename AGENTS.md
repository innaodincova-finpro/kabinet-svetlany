# Памятка по работе в хранилище «Точка решения»

Кабинет репетитора Светланы. Заказчик — Инна.
Эту памятку читать целиком перед любой работой и выполнять.

## 1. Главное требование

Все данные Светланы должны сохраняться при любой правке. Данные живут только
в её браузере и в её файле копии в OneDrive, в хранилище их нет.

Запрещено:

- менять названия записей в памяти браузера (`tochka-resheniya-v2`, `-shadow`,
  `svetlana-*`, `tochka-*`) и баз `tochka-files`, `svetlana-safety-v1`;
- переписывать или «чинить» данные при открытии кабинета;
- удалять записи, отбрасывать неполные занятия, подставлять выдуманные время,
  дату, длительность, цену;
- удалять вложения (PDF);
- работать с настоящими данными Светланы — только с выдуманными;
- ослаблять сравнение данных в проверках.

## 2. Кто что решает

- Деловые решения, распорядок и объединение запросов в `main` — только Инна.
  Запросы на объединение не объединяй.
- Технические решения принимаешь сам и сообщаешь с обоснованием. Не предлагай
  Инне выбор между техническими вариантами.
- Новое правило, порядок работы или навык — только после согласия Инны: сначала
  объясни обычными словами. Это требование переноси в каждую памятку, которую
  создаёшь.
- Работай только в этом хранилище, другие проекты Инны не трогай.
- Не объявляй конец рабочего дня и не переноси задачи.

## 3. Устройство

- `index.html` руками не правится. Он собирается скриптом
  `maintenance/safety/source/build.py` из модулей в `maintenance/safety/source/`.
  После сборки скопируй `maintenance/safety/site/index.html` и `sw.js` в корень.
- `bash maintenance/safety/check.sh` пересобирает кабинет, сверяет побайтно и
  запускает все проверки. Браузерная приёмка идёт на GitHub (Chromium, телефоны
  390 и 320, WebKit).
- Каждая правка сопровождается проверкой, которая без правки не проходит,
  а с правкой проходит.
- Каждая задача — отдельная ветка и отдельный запрос на объединение.
- Если проверка не прошла, найди причину сам и докажи её прогоном. Ошибка
  в кабинете — исправь кабинет. Ошибка в проверке — исправь проверку,
  не ослабляя сравнение данных, и объясни это в отчёте. Спрашивай Инну, только
  если затронуты данные Светланы или нужно деловое решение.
- Строка версии и дата в «Помощи» должны совпадать.

## 4. Свод правил кабинета

Сверять каждую правку, в отчёте указывать затронутые правила.

- Не стирать введённое человеком.
- Всё автоматическое отменяется кнопкой.
- Повтор не удваивает.
- Одинаковые поля везде одинаковы.
- Ничего не пропадает при закрытии.
- Один экран — одно действие.
- Цифры сходятся между разделами.
- Обычные слова.

Главное: человек открыл кабинет, ему всё понятно, ничто ни с чем не
конфликтует. Свод менять только с согласия Инны.

## 5. Отчёты Инне

  вместо «репозиторий», «отдельная версия для проверки» вместо «ветка»,
  «запрос на объединение» вместо «pull request».

  ссылки, пронумерованные шаги, где на экране кнопка. Если действий не нужно —
  напиши это одной строкой.
